# 巡检与自动化

## 每日工作流

GitHub Actions 每天香港时间 09:00（UTC 01:00）运行，也可手动触发。完整巡检成功后，访问诊断读取同一轮证据；报告生成后，滚动 Release 再次核对索引、客户端、账号、官方版本基线和访问诊断。

每次巡检均重新获取 `Gandum2077/venera-patrol-cli` 上游默认分支最新提交并安装其锁定依赖；安装前、开始巡检及分批执行前核对上游 HEAD。期间发现 CLI 更新或报告契约变化时停止，不回退到缓存旧版本。

`monitor/upstreams.json` 登记发现仓库。默认读取固定提交的 `index.json`；没有索引的仓库可在 `files` 中明确列出相对 JS 路径，例如 `Walter498/Walter` 的 `lizimh.js`。发现仅下载并提取源码实际名称、key、版本和哈希，新构建留待审阅，不自动执行或收录。

`gallhall/venerav-configs` 与 `moonskycake/venera-next` 也已登记发现。前者包含官方同步源和视频源，后者包含 debug 版本；登记仓库不代表其中条目已获漫画源兼容确认。官方原版、未严格高于官方的同 key 版本继续排除，视频能力不作为漫画阅读通过。

需要探测章节页数的源可以在审阅清单中声明 `patrolPolicy`，只允许增加请求和时间预算，并与普通预算分批执行。不能减少图片采样、开启写操作或修改收录标准；实际预算随每条巡检证据记录。栗子漫画单独使用最多 300 次请求、阶段 60 秒、整源 300 秒、单请求 30 秒。

## CI 与 Dependabot

Dependabot 每日检查 GitHub Actions 依赖，minor／patch 分组。自动合并只接受 Dependabot 验证签名的提交，要求 PR 当前 head 与成功的仓库 CI 检查一致；major、未知类型、跳过或失败的检查需人工处理。合并后显式触发 CI 和全量巡检。

CI 运行 Python 单元测试和收录标准自检，并用最新 CLI 构建、执行 VeneraX 与 Venera-Next 接口测试。源 CLI 每轮追踪上游最新版本，不由固定依赖更新流程替代。

## Release 保护

Release 只上传 `index.json` 和 `extended.json`。发布器从对应锁定构建读取来源仓库，在 Release 正文分别生成主、扩展订阅的名称、版本和来源列表；SHA-256 也写入正文。发布前先上传草稿，回读并校验附件、Latest 下载地址和哈希；全部通过后才删除旧版，最终只保留一个 Release。

附件不含报告、原始 trace、账号状态、密码、Cookie、Token、上游 JavaScript 或漫画内容。报告与证据保存于 `reports/`、`data/`；账号任务按来源白名单隔离凭据，匿名巡检不提供账号凭据，写操作关闭。

## Cloudflare 与人工验证

只将真实挑战响应识别为反爬，不根据普通 403 推断 Cloudflare 或密码错误。无账号浏览器任务只检查公开页面并等待页面自身脚本，不点击或代解验证。需要滑块、人机题或二步验证时留作本人处理；浏览器能打开页面不等于阅读链路或账号登录通过。

详情见 [访问限制报告](../reports/ACCESS_RESULTS.md)、[账号报告](../reports/ACCOUNT_RESULTS.md) 和 [绅士漫画登录说明](../reports/WNACG_LOGIN.md)。
