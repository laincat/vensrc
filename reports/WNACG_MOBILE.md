# 绅士漫画移动版解析实测

验证日期：2026-10-26（香港时间）。源版本 `1.4.1`，最低应用版本仍为 `1.3.4`。仅修改漫画源及相应测试、说明和固定引用；未修改或构建 VeneraX。

## 先确认可修复的故障

同一站点会根据 User-Agent 返回不同页面。先匿名抓取桌面／iPhone UA 的 20 份真实 HTML，再用 VeneraX 2.3.6 与 Venera-Next 1.18.0 的原始 JavaScript bootstrap 执行旧源。两套接口都复现：桌面版可解析，移动版首页空列表，分类、搜索和详情因旧选择器不匹配而报错。固定图片目录仍能解析，说明不是所有阅读接口失效。

| 页面 | 旧源问题 | 本次核对后的处理 |
| --- | --- | --- |
| 首页 | 只读桌面版 `title_sort/bodywrap`，移动版得到空列表 | 读取 `.imgBox` 分区、标题与漫画卡片，未知首页明确报错 |
| 分类／翻页 | 移动版 DOM 不同；第二页混入广告卡片 | 同时解析两套卡片结构，仅接受 `photos-index-…aid-…` 漫画路由 |
| 卡片标题 | 连载角标可能先于真正标题命中 | 优先读取独立标题，仅在搜索卡片没有独立标题时读取覆盖层，不把角标当名称 |
| 搜索 | 移动版标题在图片覆盖层，没有 `a.txtA`；没有桌面版总数节点 | 适配真实覆盖层标题，页数取页面实际分页链接，不虚构总条数 |
| 排行榜 | 移动版使用 `.rand_rq .itemBox` | 核对图片、标题和分页，在线测试前两页 |
| 详情 | 移动版使用 `#comicName/#Cover/.sub_r`；封面可能有四个前导斜杠 | 读取真实标题、封面、分类和投稿者，规范化图片地址 |
| 连载 | 移动版章节编号在 `li[data-chid]`，首屏只有 12 章 | 读取章节条目及 `data-total/data-limit`，核对第二页补齐 14 章 |
| 缩略图 | 移动详情没有桌面缩略图网格 | 从既有图片目录分段取得地址；没有伪造图片 |
| 收藏 | 未取得真实会员列表，不能仅凭 HTTP 200／标题就算列表通过 | 保留会员权限检查；新增移动卡片结构分支和未知版式拒绝，单独列为待实机验证 |

未强制改成桌面 UA，避免更换网页登录时的客户端身份。会员请求继续禁用缓存，不降低登录或订阅标准。

## 最新 CLI 在线复测

每次执行前查询上游 HEAD，确认本轮 CLI 为 `dd6ded39844e56902d3880b1fc1c201a6d1d1fda`。加载两套既定原始客户端 bootstrap，注入的仅是公开 iPhone UA，没有账号、Cookie、Token 或伪造登录标记；关闭写操作，实际请求站点。

| 接口环境 | 通过 | 失败 | 跳过 | 实际执行范围 |

| VeneraX 2.3.6 | 23 | 0 | 14 | 搜索／分类／排行榜前两页、首页、固定详情、图片目录、图片及缩略图下载和解码 |

整次状态仍是 `partial`。跳过包含 Cookie 登录、WebView 交互、会员收藏、写操作及设置按钮，不计通过。源测试 15 项与双客户端桥接测试 8 项通过，其中收藏列表是置换内容的结构回归，不能替代真实会员页面。

## 尚未确认的部分与 App 验收

电脑端无法操作用户 iPhone 上的 VeneraX，本次没有实机网页登录、本人收藏列表或重启后的持久化结果。公开页面故障已复现并修复；不能据此保证所有登录态页面均已兼容，也不能把“可注销”当成服务器已接受全部会员请求。

更新订阅和已安装源至 `1.4.1` 后，可直接打开首页、分类和固定详情检查浏览；已有 Cookie 无需为了这次解析修复而清空。然后在源设置点击“检查登录与浏览”，分别看会员页与收藏列表结果，完整关闭并重开 App 后再检查一次。只需提供脱敏后的阶段结果，不提供 Cookie、账号密码或收藏内容。

若会员页通过而收藏解析失败，继续核对该会员列表的真实结构；若会员页未通过，收藏显示跳过；若首页／详情仍失败，应按对应请求诊断，不直接归结为 CF。
